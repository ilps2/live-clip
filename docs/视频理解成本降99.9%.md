# 视频理解成本降 99.9%：给 LLM 一张"视频信息层"

> 让 LLM 读视频的**信息层**（几千 token），而不是逐帧像素（百万 token）。
> 先低成本判断视频类型，自动选择最便宜且够用的理解策略。
> 2026-08 更新：10 个真实 B站视频端到端实测，0.034 元/视频，一条命令出摘要+问答。

## TL;DR

- 视频喂给 LLM 很贵：1 分钟 1080p 逐帧 ≈ 180 万 token
- 但 70% 的视频查询**不需要逐帧视觉** —— 播客听语音、运动看轨迹、产品看对象
- 方案：**先判断类型，再选策略**，用"信息层"代替"原始像素"喂 LLM
- 实测：10 个真实 B站视频（8 类别 × 1~28 分钟）理解链路 10/10 成功，token 降 99.95%+，**单视频 LLM 成本 0.034 元**
- 一键接口：`B站链接 → 下载 → 分析 → 摘要 + 问答`（[understand_video.py](https://github.com/ilps2/live-clip/blob/main/understand_video.py)）

## 一、问题：视频理解为什么贵

当前大模型处理视频，主流方式是**逐帧采样**：抽 N 帧，每帧编码成约 1000 token 的图像块喂给多模态模型。

```
1 分钟 1080p 视频 × 30fps = 1800 帧 × 1000 token = 180 万 token
```

成本账（1 小时视频）：

| 方案 | token | 相对成本 |
|------|-------|---------|
| 原始逐帧（24fps） | ~8,640 万 | 100% |
| 纯 ASR（语音密集） | ~2 万 | 0.02% |
| AVIS 信息层 | ~2.5 万 | 0.03% |

更关键的是：各家模型都在**重复同一件事** —— 把同一段视频的像素解码成张量，各跑一遍编码器。没有人做"一次编码、多方复用"的中间层。这就是我们要补的位置。

## 二、核心思路：视频信息层 + 类型自适应路由

关键洞察：**不是所有视频都需要"看见每一帧"**。

- 播客/讲座：语音是 95% 的信息 → 纯 ASR 就够
- 静态风景：画面几乎不动 → 稀疏帧
- 运动/体育：对象轨迹才是语义 → MV + 轨迹
- 直播带货：语音 + 画面结构混合 → 全套信息层

所以正确做法是：**先用免费信号判断视频类型，再选择最便宜且够用的策略**。

```
拿到视频
  ├─ ① 免费信号探测（<1s）
  │     MV 运动矢量（H.264 码流免费）+ 帧差 + 色彩分布 + ASR（8-12x 实时）
  ├─ ② 类型分类（规则，零模型）
  │
  ├─ 静态风景 ──→ 稀疏帧理解
  ├─ 语音密集 ──→ 纯 ASR（播客/讲座/解说）
  ├─ 运动密集 ──→ MV + obj_tracks（对象轨迹）
  ├─ 混合/直播 ──→ ASR + 场景 + 轨迹 全套
  └─ 输出：类型 + 推荐策略 + 预计 token
```

## 三、实现：AVIS 的三个新能力

基于 [live-clip](https://github.com/ilps2/live-clip) 已有的 AVIS 管线（MV/ASR/场景分类，一次编码多次复用），新增：

### 1. `avis classify` — 类型自适应路由

只用免费信号判断类型，推荐理解策略：

```bash
avis.py classify 视频.mp4 --asr
# → {"type":"speech_dense","recommended_strategy":"pure ASR transcript",...}
```

判定信号（全部零模型成本）：帧差（运动量/静态率）、色彩分布（自然风景启发式）、ASR 语音覆盖率、MV 运动矢量（码流免费读取）。

### 2. `avis encode --obj-tracks` — 对象轨迹信息层 + YOLO 语义

OpenCV MOG2 运动对象检测 + IoU 追踪，输出 `obj_tracks.jsonl`：

```json
{"obj_id": 4, "appear_t": 0.5, "disappear_t": 8.2, "motion": "bottom→top",
 "speed_px_s": 28.2, "class": "person", "centroid_path": [[0.5, 120, 300], ...]}
```

- 本地 yolov8n（6.2MB）对运动对象打语义标签（person/cell phone/…），全帧检测 + IoU 匹配，实测**误检为零**
- 无语音视频（纯 BGM）的语义空白由 YOLO 填补：舞蹈视频识别出 5 个 person，产品评测识别出"手机+人物"

### 3. `avis prompt` — 融合提示词（视频 RAG）

把 ASR + 场景结构 + 对象轨迹（含类别）融合成一段 LLM 提示词，模型无关（DeepSeek/GLM/Claude 都能读）：

```bash
avis.py prompt 视频_avis/
```

## 四、验证：10 个真实 B站视频端到端

2026-08 用 `bilibili-downloader` 下载 10 个真实 B站视频（8 类别 × 时长 1~28 分钟 × 360p~1080p 多画质），完整跑 下载→encode→classify→prompt→LLM：

| 视频 | 类型 | 信息层 tok | 原始逐帧 tok | 降本 | 理解质量 |
|------|------|-----------|-------------|------|---------|
| 舞蹈 (360p) | motion_dense | 926 | 135 万 | 99.98% | 5 person + 数拍口令 |
| 数码推荐 EDC | speech_dense | 1,166 | 540 万 | 99.98% | 耳机/AirPods/阅读器全中 |
| 恐怖动画 | motion_dense | 643 | 234 万 | 99.97% | 对话主题 + 7 边界 |
| 美食吃播 | motion_dense | 899 | 540 万 | 99.98% | 麻辣饭+炸鸡+博主名 |
| 生活 Vlog | speech_dense | 1,305 | 540 万 | 99.98% | 台风天/宠物/菜品 |
| 户外烧烤 | speech_dense | 1,091 | 540 万 | 99.98% | 家庭出游+穿串 |
| 蒙眼摸车 | speech_dense | 1,202 | 540 万 | 99.98% | 奔驰/小米/颜色 |
| 游戏实况 | speech_dense | 649 | 357 万 | 99.98% | 解说+精确边界点 |
| 科普解说 | speech_dense | 1,193 | 540 万 | 99.98% | 主题精准 |
| 手机评测 (1080p) | motion_dense | 870 | 186 万 | 99.95% | 2 手机+1 人（纯 BGM 无语音） |

**关键结论**：

1. **语音主导类全部高质量** —— 7/10 视频的描述与真实内容高度吻合（产品名、人名、剧情、细节都对）
2. **无语音视频靠 YOLO 兜底** —— 纯 BGM 视频（舞蹈/评测）从"只描述运动"进步到"识别出人和手机"
3. **成本端到端实测** —— 21 分钟电影解说视频：下载+分析+理解 220 秒，**LLM 成本 0.034 元**，降本 99.99%
4. **消融实验（此前）** —— 融合 8/8 vs 纯 ASR 6/8 vs 纯轨迹 1/8 vs 逐帧描述 3/8：结构化信息层不是妥协，是更可靠的表示

## 五、修复历程：三个真实数据暴露的问题

10 视频实测逼出了三个修复（都在 repo 里）：

1. **场景边界误读**：prompt 把 scenes.csv 逐秒标签行数当边界数（"180 个边界"），改为从标签重算真实边界 + 分布 —— 修正后游戏视频给出精确边界时间点
2. **ASR 空转写**：whisper tiny 对部分视频 0 段，自动升级 base 重试；用 base 复测确认"纯 BGM 无解说"视频路由 motion_dense 是**正确的**而非分类失误
3. **无语音语义空白**：集成 YOLOv8n 对象标签，误检清零

## 六、设计取舍（诚实说明）

- **MOG2 轨迹在低清/镜头跟随下碎片化**：360p 舞蹈视频 blob 分裂，person 召回受限（5/12）；1080p 源效果显著更好。换 deep-sort 级跟踪是下一步
- **YOLO 只覆盖 COCO 80 类**：食物、产品型号等专业对象仍 unknown，可换自定义模型
- **ASR 错别字**：tiny 模型转写噪音影响精确型号提取（"小米83 Pro"），需要 small 模型或纠错
- **信息层丢像素级细节**：表情、纹理、OCR 需要多模态兜底 —— 信息层拦截"不需要逐帧"的 70% 查询

## 七、分级成本路线（L0/L1/L2）

```
L0 内容级（摘要/问答/分类/剪辑）→ 信息层，0.034 元/视频       ← 80% 需求
L1 视觉级（对象/事件细节）       → L0 + 按需抽 3-5 帧 + VLM
L2 证据级（逐帧审查）            → 仅对 L0/L1 命中的可疑片段展开
```

常规需求的 80% 永远走 L0；只有真正需要画面细节才升级 —— 整体成本仍比"全部逐帧"低 2~3 个数量级。

## 八、定位与展望

> AVIS 不替代多模态模型。它拦截"不需要逐帧视觉"的查询，让这些查询便宜 ~50 倍且模型无关；真正需要"看见每一帧"的 20-30% 留给多模态模型。

未来方向：
- 大规模 benchmark（100+ 视频，第三方评估）
- "一次编码、多方复用"的中间格式标准化
- 实时流式信息层（边接收边建索引）
- 把 L0 接口包装成服务（链接进 → 摘要/问答/剪辑建议出）
